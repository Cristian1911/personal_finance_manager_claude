The first PR: the engine's walking skeleton

What's in it

  • packages/shared/src/engine/: the command model (id, type, payload, timestamps), a storage "port" (the operations a command needs), and one command: captureManualTransaction (validate, idempotency key, balance of counted accounts).
  • Two adapters: SQLite (the phone) and Postgres (the server), behind the same port.
  • One contract test suite that runs the command against both adapters and asserts identical results, including a replayed command (applied once) and an out-of-order edit (latest wins per field).
  • Migrations for commands and field_versions, applied to the dev project only.

What it proves, and how to check it

  • Proves: one piece of logic really can run identically on phone and server (S1-1), replays are harmless, and conflicts resolve by the S1-2 rule.
  • No UI, no production changes, nothing the web app or today's mobile app can notice.
  • Check: pnpm --filter @zeta/shared test green; the same suite green against the dev project's Postgres; pnpm build clean.
  • The second PR is the UI shell: tokens (4 sets), primitives, the (v2) routes behind the flag, SQLCipher, and the widget gallery screen.
